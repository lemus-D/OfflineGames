# Agent instructions

Read this first. It is short on purpose; the long versions are in `docs/`.
Prioritize readability over cleverness. Ask before making architectural
changes; do not ask before making routine ones.

## What this project is

Small games, played offline, sold from a website. Each game is an
**installable PWA**: the customer buys it, opens it, installs it, and a service
worker precaches everything so it runs with no network.

`moon-rover` is a git submodule pointing at a finished reference game
(REGOLITH). It is the quality bar — "fun to play, good graphics" — and it is
the proof that the approach works: a complete 3D game in 379 KB gzipped with
zero asset files. Fetch it with `git submodule update --init --depth 1`, then
read `moon-rover/README.md` and `moon-rover/docs/ARCHITECTURE.md`. Copy its
doctrine, not necessarily its structure.

## Three workflows

- **Starting a game from a pitch** → use the `new-game` skill
  (`.cursor/skills/new-game/`). It asks the owner a short questionnaire (the
  **QC brief**: run length, inputs, sound level, tone, and so on), writes the
  answers into the plan, copies the scaffold from the reference game, and sets
  the build order. The brief is asked, never guessed.
- **Before saying any game or change is done** → use the `game-qc` skill
  (`.cursor/skills/game-qc/`). It runs mechanical gate 0, then **spawns a
  fresh** `game-playtest` critic (not the builder) that judges the build
  against the original pitch, records gameplay, reviews motion, and commits
  `<Game>/PLAYTEST.md`. The builder may respond for up to three rounds
  (feel **and** design/content). A game is not done because smoke is green.
- **Independent playtest** → use the `game-playtest` skill
  (`.cursor/skills/game-playtest/`) in a fresh agent when you want a critic
  pass without the builder context.

`CLAUDE.md` is a one-line pointer to this file so Claude Code reads the same
instructions.

## Standards

Non-negotiables. Each one is explained in `docs/TECHNICAL-DECISIONS.md`.

1. **No build step, no runtime dependencies.** Plain ES modules across real
   files, served by a zero-dependency static `server.js`. The source in the
   repo is the thing that runs.
2. **All art and audio are generated by code. Zero asset files.** No images,
   no sound files, nothing to license. Icons are inline SVG data URIs.
3. **Never use `Math.random()` in game logic.** Seed everything through
   `src/core/rng.js`. Simulation runs on a fixed timestep inside
   `PlaySession.step(frameDt, controls)`; rendering reads the result.
4. **Namespace and version every storage key** — `apex.v1.profile`. All
   `localStorage` access goes through `src/core/save.js`, which stores
   `{ schema: N, ... }` and falls back to a fresh profile when it cannot read
   one. Never key saved state by array index.
5. **Content lives in data, not in logic.** Upgrades, animals, pickups and
   celestials are rows in `src/game/content.js` applied by one generic function.
6. **Verify in the running game, not by reasoning.** Claims about behaviour
   that were not observed are not findings. Run it, then say it works. Put
   before/after numbers in the commit when you tune something.
7. **Don't trade fun, feel or clarity for bytes.** Download size is not a
   constraint. Keep games small as a consequence of rule 2, not as a goal.
8. **Shared code is copied, not shared.** No common engine package. Copy
   `rng.js`, `save.js`, `input.js` from the reference game and let them
   diverge.

## House layout

Every game follows the same shape. Deviate only with a reason written in the
game's plan.

```
<Game>/
  <GAME>PLAN.md          loop, controls, QC brief, non-goals, open questions
  PLAYTEST.md            critic report (committed; NOT shipped / not in sw.js)
  index.html             shell, HUD markup, inline CSS, inline SVG icon
  manifest.webmanifest   installable; icons are data: URIs
  sw.js                  precache list — every file under src/ must be listed
  server.js              zero-dependency static server, unique default port
  package.json           scripts: start, smoke
  smoke.mjs              headless checks (per-game; genres differ)
  src/main.js            boot, menus, frame loop, DOM HUD, SW registration
  src/core/rng.js        seeded PRNG (+ noise if needed)
  src/core/save.js       the only file that touches localStorage
  src/core/input.js      keyboard + pointer/touch → one controls object
  src/core/audio.js      procedural WebAudio, gated on user gesture
  src/game/content.js    data tables and constants, including FIXED_DT
  src/game/play.js       PlaySession: pure simulation, no DOM, no canvas
  src/game/draw.js       Canvas 2D rendering from session state
```

## Commands

```bash
git submodule update --init --depth 1       # fetch moon-rover
cd <Game> && npm start                       # dev server on the game's port
cd <Game> && npm run smoke                   # headless checks
node .cursor/skills/game-qc/scripts/check-game.mjs <Game>   # mechanical gates
```

Service workers need a secure context, so a PWA cannot be tested from
`file://`. Always use the dev server. Hard-refresh after pulling; the SW cache
name must be bumped whenever a precached file changes.
